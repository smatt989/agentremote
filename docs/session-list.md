# Session activity and unread responses

Session lists on Mac and iPhone sort newest first by the last completed, nonempty user or assistant text message. Streaming output, tool events, status polling and history replay do not move a session. On iPhone, Chats uses compact rows with a two-line title, agent/project metadata, and a short last-message time. An unread dot marks a new assistant reply; only working, waiting, error, or external-client states are shown. Full paths and repeated Idle/Read labels are omitted. Knowledge is a separate tab, search stays above each list, and the Settings menu includes Mac selection. The tab bar is hidden inside conversations to leave room for the composer. Mac rows retain their detailed timestamps and read labels. Sessions without cached completed messages use their creation time for ordering. Historical provider timestamps can be approximate when the provider only supplies a thread timestamp; replay preserves the recorded completion time.

Unread refers to the latest completed assistant response. The Mac stores a shared receipt for its exact message/content version. Loading history never marks it read. The UI sends a receipt after the latest conversation content is displayed at the bottom in the active app/window. Background polling, reading earlier history and partial output do not acknowledge a response. A response arriving after the displayed snapshot remains unread. Receipts persist across restarts and synchronize across paired clients; viewing a conversation in an independent Claude/Codex client cannot mark it read.

Responses from before this feature initially appear unread because prior viewing was not recorded. Older clients can keep chatting but cannot send read receipts.

API: session list/detail responses include `lastCompletedAt`, `lastCompletedRole`, `latestAssistantMessageId`, `latestAssistantToken` and `unread`. `POST /sessions/:id/read` accepts `{ "token": "<displayed latestAssistantToken>" }` and returns the current session. It is authenticated and works through the encrypted phone relay. Stale receipts are harmless and deletion removes the session's receipt.
