# Automatic local memory

Agent Remote stores its knowledge library on the paired Mac, in `~/Library/Application Support/AgentRemote/`. There is no hosted memory database or OpenAI memory service. SQLite holds the searchable records, provenance, topic hierarchy, learning cursors and deletion markers; `memory/*.md` contains readable, atomically refreshed exports grouped by source session and topic. The SQLite records are authoritative; editing an exported Markdown file does not change retrieval.

Start talking normally. There is no topic selector, biography, memory introduction, or requirement to say “remember this.” Each submitted prompt receives at most about 4,200 characters of relevant prior context (including up to three knowledge-page previews, limited to 1,200 characters), selected by local full-text search; already supplied snippets are not repeatedly injected during the same loaded session. Agents also have `memory_search` and `memory_topics` tools for retrieving context as the subject changes or terminology differs. Topic paths are generated from evidence, not configured by the user. Search has hard result/size limits and reserves space for recent original messages so corrections can be seen before consolidation.

New conversation text is searchable immediately. After two minutes of inactivity (or a session ending), a serial background worker starts a bounded job per 30-second tick, alternating transcript extraction with wiki organization or article writing/review when both have work. It can also read accessible inactive provider histories, one per tick, without resuming them. It does not need the phone to be open. The initial history backlog takes time to learn; it is not imported in one costly burst. Long active turns stay searchable but are not summarized until the turn settles.

Cloud computation and local storage are separate: relevant excerpts go to the selected session's provider. Background extraction uses that same provider, with the existing local sign-in: Claude uses `claude-sonnet-5-5`; Codex uses its built-in default with low reasoning effort and user configuration ignored. No extra API key is required. These calls consume provider usage. Override the worker models with `AGENT_REMOTE_MEMORY_MODEL` (Claude) or `AGENT_REMOTE_MEMORY_CODEX_MODEL` (Codex). The worker uses ephemeral/no-session-persistence mode, isolated temporary working directories and disabled tools/customizations. Codex built-in memory generation/use is disabled for this worker. Temporary files are removed. The relay only transports encrypted requests and responses; it never receives a plaintext memory library. Provider data-handling policies still apply to model requests.

Every saved note includes an exact source quote and message/session IDs. Unsupported source IDs/quotes and malformed records are rejected. User statements are distinguished from provisional assistant reports; facts and decisions persist regardless of source, while temporary progress notes expire from automatic retrieval after 14 days. Existing facts and decisions previously hidden by expiry are restored; forgotten or deleted sources are not restored. Explicit corrections retain their evidence, and conflicting statements are kept for the agent to resolve using scope and dates. This is retrieval with source tracking, not a guarantee that every model inference or memory is correct. Common credential formats are filtered, but this is not a comprehensive secret detector.

The optional **gear → Memory** screen lets you inspect/search learned notes and their supporting quotes. Swipe a note to Forget: all saved notes derived from that source message are removed and the source message is excluded from future memory retrieval/extraction. The original conversation remains. Already-running provider contexts may still contain previously supplied information. Deleting a session removes its derived notes, raw search entries and Markdown export; late extraction results cannot recreate a deleted session. Corrections can also be made simply by stating the correction in conversation.


## Canonical knowledge wiki

The [knowledge wiki](knowledge-wiki.md) organizes evidence into persistent subject articles, overviews, and procedures. Articles combine evidence across conversations; processing windows never determine page boundaries. The editor establishes subject structure, routes claims, merges overlaps, writes revisions, and checks their support. Aliases and redirects preserve discovery and old links.

Agents use `knowledge_search` for bounded previews and `knowledge_read` for an article, outline, breadcrumbs, children, and backlinks. Reads return at most 7,000 Markdown characters with `nextOffset` and a revision for consistent pagination. Raw memory remains available for recent corrections and verification. Retrieval uses local full-text search plus explicit subject relationships, not embeddings.

The Mac and iPhone readers support inline article links, contents, sources, and navigation history. Authenticated routes remain `GET /knowledge` and `GET /knowledge/page`; no relay deployment is necessary. Exports are `knowledge/<topic>/article.md` and `knowledge/index.md`. SQLite is authoritative.

Articles are kept current by per-article stewards, area curators, a whole-wiki librarian and a file verifier that coordinate through talk pages; see the wiki documentation. Source removal invalidates derived text, including overviews and stored revisions. Failed model work preserves evidence and retries after 15 minutes. Background operation is required for ongoing editing. See the wiki documentation for model settings, migration behavior, and tests.

## Clarification questions

Agents can display one to three structured questions using `ask_question`; options render as tappable choices with an always-available text field. Nothing is selected or submitted automatically. Continue submits all answers, and the agent resumes. Necessary native Codex `item/tool/requestUserInput` requests use the same cards. MCP questions persist through an app/service restart; native pending RPC questions are cancelled after disconnection/restart because their original request can no longer be answered. Interrupt/end cancels pending questions. The normal composer is disabled while a question is pending; its text field supports any alternative answer.

## Validation and limits

- Unit/API tests cover evidence, immediate recall, corrections, deletion/forgetting, idle learning, retries, auth, native question response shape and answer deduplication.
- `node scripts/smoke-memory.mjs claude|codex` checks real provider extraction from a synthetic Hex/domain-model example and exclusion of assistant speculation.
- `node scripts/smoke-context-session.mjs claude|codex` creates disposable real sessions, verifies recall, an actual MCP question and answer continuation, then deletes only its fixtures.
- The exact iPhone CryptoKit/URLSession transport verifies memory search/forget and question/answer retries through the public relay.
- Retrieval is local full-text search plus agent-driven topic exploration, not embedding search. Very indirect references may need an additional search or clarification. Histories are imported through the existing bounded provider history APIs; there is no promise to recover every detail of every old transcript.
- Push notifications were explicitly deferred; no APNs configuration or code was added.

## Evidence learning improvements

The learner now includes text tool requests/results alongside conversation text. Requests are evidence of intent, not successful execution. Facts derived from tool output remain labeled as tool evidence requiring verification. Images, reasoning blocks, sleep events, and memory-retrieval calls/results are excluded to avoid binary payloads and feeding recalled claims back into learning. Recognized credentials are redacted before extraction. Long sources continue over multiple bounded batches instead of losing everything after 6,000 characters.

Active sessions can learn earlier turns up to the most recent user-message boundary; the current turn waits until a later user turn or the normal idle learning window. This is incremental background work, not instantaneous learning after every tool call. Extraction and wiki synthesis still alternate with one model call per tick and retry backoff.

Claude project reference notes in the transcript project's `memory/*.md` directory (excluding the index `MEMORY.md`) are imported into shared searchable knowledge. No home-directory crawl is performed. Each scan is capped at 64 files, 64 KB per file and 512 KB total; symlinks are excluded. Files beyond these limits are not imported. References retain the original file path, modification date, project-specific topic and provisional provenance. Their complete accepted text is split into bounded source chunks. Changed files replace their prior imported evidence; deleted files are removed on the next scan of that folder. Forgetting the reference suppresses subsequent re-imports. Reference notes are data, never instructions. Codex can retrieve these shared pages too; this does not import every provider's private memory format.

A bounded, idempotent backfill operation can revisit the last 400 stored messages in a selected session. Existing evidence deduplicates, forgotten sources remain hidden, and a repeated durable classification can correct an earlier temporary classification. It does not automatically reprocess the entire archive or reclassify all old progress notes as facts.
